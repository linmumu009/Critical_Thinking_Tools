# 模式 2：Codex 研究问题发现

模式 2 只有一个业务目标：**为大模型文本后训练、数据合成、GRPO/RLVR 及相邻方向发现一个值得投入实验资源的研究问题。**

它不是 benchmark 评分器，不是第二套 API，也不是通用聊天模式。执行者是当前 Codex；它使用当前任务可用的检索和本地分析能力，不读取 `model-config.local.json`，不调用用户填写的外部模型 API，也不要求用户逐项评分。

## 固定交付

每次完整运行只交付：

1. 一个主研究问题；
2. 两个备选问题；
3. 支撑机会判断的来源证据与最接近的既有工作；
4. 可证伪假设、反假设、变量、基线和最小实验；
5. 最可能导致论文被拒或结论不成立的反方论证；
6. 明确的保留、缩小、改写或淘汰条件。

“听起来新颖”不算发现。只有经过真实文献碰撞、可证伪性和最小实验检查的问题才能成为主问题。

## 文件

- [研究领域画像](research-profile.json)：固定业务范围与默认约束。
- [执行协议](PROTOCOL.md)：当前 Codex 的自主工作流。
- [产物规范](SESSION-SCHEMA.md)：证据、候选和最终问题契约。
- `research_question_session.py`：创建和验证会话产物，不调用任何模型 API。

## 使用方式

当用户开始一次问题发现任务并选择模式 2 后，当前 Codex 应直接读取本目录协议，自主完成检索、候选生成、反证和收敛。若用户没有补充更窄的主题，默认在整个领域画像内寻找机会，不把补充信息作为启动前置条件。

最终会话保存为 JSON 后，可运行：

```powershell
python modes/codex-research-question/research_question_session.py validate --session <会话文件> --complete
```

验证器只检查产物完整性和内部一致性；它不能证明问题真的新颖或重要，最终判断仍必须由所列一手来源和实验结果承担。
