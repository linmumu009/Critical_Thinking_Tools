## 结论

本轮发现一个相对四个在位问题更适合**当前下一笔研究预算**的新主问题。优势来自 2026 年异步 RL 现实信号密集、一天级缓存重放即可形成强反事实，以及答案会直接决定是否建设版本平衡/顺序校正队列；这不表示它在长期科学价值上永久取代在位问题。

## 主问题

**短标题：** 完成顺序偏差

**白话问题：** 同一批训练轨迹只是完成先后不同，会让异步训练的更新方向变化吗？

**为什么值得问：** 若仅到达顺序就改变更新，应先建设顺序随机化或版本平衡，而不是只限制最大陈旧度。

**正式核心问题：** 固定 rollout 集合和行为策略后，真实完成顺序是否增加相对版本同步更新的梯度方向误差？

### 次级问题树

- 机制：快速完成轨迹是否获得更高的早期有效权重？
- 边界：时延与长度或难度无关时效应是否消失？
- 干预：版本平衡批处理能否恢复同步 oracle？

核心问题只表达一个未知；控制条件与工程方案保存在契约中，没有塞回问题句。

## 它服务的决策

在 2026-09-17 前，决定是否投入 1–2 周工程和小模型 GPU，建设顺序随机化、版本平衡队列与慢子群审计。若 A 成立，推进这些基础设施；若 B 成立，把预算转向最大 lag×学习率、log-ratio 尾部或路由一致性；若只在高相关子群成立，则局部启用并继续复现。

## 为什么不是常识或已被直接回答

显然基线只是“陈旧 rollout 可能使异步更新有偏”。本题剥离了陈旧程度和轨迹集合，问的是：固定 rollout 与行为策略后，**完成顺序本身**是否增加相对版本同步更新的方向误差。

三路先行研究检索覆盖了精确问题、完成时延机制和异步联邦学习中的快参与者占优。最接近的 AReaL、DORA、StaleFlow、陈旧—学习率标度律与自适应信任域研究已经处理陈旧、长度倾斜和高错配尾部，但本轮未找到“固定轨迹与行为策略，仅随机化到达顺序，并报告慢子群 oracle”的直接答案。因此判定为 **incremental**，不是“无人研究”的绝对新颖性声明。

## 最小现实试探

1. 从公开异步 RL 实现导出 256–512 条、至少两个行为版本的缓存轨迹及完成时间。
2. 固定 prompt、生成文本、奖励、行为 logprob、token mask 和总 token。
3. 分别按真实完成顺序、版本内随机顺序和版本平衡顺序重放 20–50 次更新，每种三随机种子。
4. 主要结果是相对版本同步 oracle 的梯度 cosine/范数误差，以及慢四分位的累计有效权重。
5. 只有真实顺序的 cosine 恶化至少 0.05、方向跨种子一致，并随人为注入的时延—长度/难度相关增强而呈剂量反应，才继续投资。

阶段 7 的玩具二次损失反例中，相同两项损失以相反顺序逐步更新的终点相差 0.08，而整批聚合差异为 0。它只证明该效应可被实验区分，不证明真实 LLM 已存在该效应。

## 两个备选

### C07：动态过滤净增益（11/12，缩小）

- 白话：动态过滤变强，是信息用得更好，还是只让中等难度题出现更多？
- 正式：DAPO 式动态过滤的大 k 覆盖增益是否超出其中等难度 prompt 重加权效应？
- 最小试探：组大小 8 时，解析入选概率从成功率 0.5 的 0.992 降到成功率 0.01/0.99 的约 0.077；下一步以缓存 rollout 比较原始过滤、共同支持区校正过滤和不筛选的等 token 更新。

### C10：机制覆盖测量（10/12，缩小）

- 白话：在能看清解法结构的任务里，机制覆盖比 token 熵更能预测大 k 吗？
- 正式：在可抽取解法图的任务中，机制簇覆盖是否比 token 熵更能预测大 k 正确覆盖？
- 最小试探：在 20–30 道可抽取运算图/控制流图的问题上，控制表面改写后比较机制簇覆盖与 token 熵对时间外大 k 正确覆盖的增量预测。

## 限制
