# 校准记录

这里记录正式实验前发现的 Oracle 问题。校准运行不计入正式结果，也不能被当作方法效果证据。

## 2026-08-19：research-01 / 条件 B

- 状态：废弃校准运行。
- 发现：模型询问“第 12 周前是否收集过与试点相同的短期结局、结果如何”，事实表包含相应周度轨迹，但关键词 Oracle 错误返回“无法回答”。
- 影响：低估关键未知命中率和 critical fact hit rate，并诱发一次重复追问。
- 修复：为周度轨迹事实补充“短期结局”“第 2 周”“更早的测量”“结果如何”等触发表达。
- 防复发：加入原始问题文本的回归测试，要求在已揭示终点时间差后命中 `f2`。

## 2026-08-19：product-01 / 条件 A

- 状态：失败尝试，不计入正式结果，修复后从同一运行编号重试。
- 发现：模型在提问阶段使用 `DECISION: <option_id>` 提前结束，而不是控制器要求的单独 `DECIDE`；旧控制器将其视为致命格式错误。
- 影响：会话未保存，批次按安全策略在 `QD-003` 停止，后续条目没有运行。
- 修复：接受有效的提前 `DECISION` 作为结束提问信号，随后仍请求标准最终决定和理由；同时在会话中记录 `protocol_deviations`，不掩盖模型未严格遵循格式。
- 防复发：新增提前决定的完整 API 会话回归测试。

## 2026-08-19：operations-01 / 条件 C

- 状态：废弃 `QD-005` 首次运行；批次在下一条首问后人工中断，`QD-006` 未保存、需重试。
- 发现：模型询问东区是否有可立即承接货量的替代运输能力，旧 Oracle 仅因问题出现“东区”便错误返回地区集中度事实，没有回答运力可行性。
- 影响：`QD-005` 的问题—答案配对失真，自动覆盖指标不可信。
- 修复：移除地区事实中过弱的单独“东区”触发词；为行动可行性补充 H2/H4 线路余量事实及“替代方案、剩余运力、接管、切换”等触发表达。
- 防复发：加入该原始问题的回归测试，必须命中替代线路事实 `f6`，不得命中地区事实 `f1`。

## 2026-08-19：research-01 / 条件 C

- 状态：`QD-009` 在首问后人工中断，未保存、需重试。
- 发现：模型询问“复制研究的主要结局测量距离干预结束的时间是否与试点一致”，事实表包含第 2 周与第 12 周的答案，但“测量”和“时间”被其他词隔开，未命中旧的连续触发词“测量时间”。
- 影响：若不修复，会把条件 C 的一个关键且可回答问题误记为不可回答。
- 修复：补充“主要结局测量、测量距离、距离干预结束、是否与试点”等表达。
- 防复发：新增该原始问法的回归测试，必须命中终点时间事实 `f1`。

## 2026-08-19：Benchmark v0.2 / product-02 / 条件 B

- 状态：废弃 `CAL2-001` 首次运行，修复后从同一校准编号重试。
- 发现：模型询问内容从提交到成功发布的成功率/失败率，旧 Oracle 因单独触发词“发布”将其错配为软件版本上线事实 `f3`，而不是上传阻断事实 `f2`。
- 影响：虽然返回事实与根因相关，但没有回答所问指标，关键事实命中路径失真。
- 修复：从软件变更事实移除过宽的“发布”，改为“版本发布/功能发布”；为上传事实增加“发布成功率、发布失败率、提交内容、成功发布”等表达。
- 防复发：新增该原始问题回归测试，必须命中 `f2`，不得命中 `f3`。

## 2026-08-19：Benchmark v0.2 / operations-01 / 条件 B

- 状态：`CAL2-003` 在第 3 问后人工中断，未保存、需重试。
- 发现：模型询问是否可临时改用其他承运商/路由绕开 H3，以及替代方案是否有足够承接能力；事实 `f6` 已包含 H2/H4 余量，但旧触发词只覆盖“替代方案、剩余运力、切换”等表达。
- 影响：一个直接验证行动可行性的高价值问题被误记为无答案。
- 修复：补充“承接能力、足够能力、绕开/绕过 H3、临时改用、其他路由”等释义。
- 防复发：新增该问法的回归测试，必须命中替代线路事实 `f6`。

## 2026-08-19：Benchmark v0.2 / project-03 / 条件 C

- 状态：`CAL2-010` 在初始概率校验时停止，未保存、需重试。
- 发现：模型返回的四项 `PRE_PROBABILITIES` 之和不等于 1；旧控制器立即终止，无法区分判断失败与可修复的格式错误。
- 影响：本条没有进入问题阶段，后续 `CAL2-011/012` 未运行。
- 修复：初始或最终概率格式无效时允许一次纯格式修复重试；不提供新事实、不改变任务，原始输出记录到 `protocol_deviations`；重试仍失败才终止。
- 防复发：新增初始概率之和错误后一次修复成功的端到端测试。

## 2026-08-19：Benchmark v0.2 / project-03 / 条件 C（第二次）

- 状态：`CAL2-010` 在第 2 问后人工中断，未保存、需再次重试。
- 发现：模型询问应用层发布或配置变更是否与成本激增时间重合，以及每请求资源消耗是否增加；缓存命名空间迁移事实 `f2` 可以回答，但旧触发词没有覆盖这组因果问法。
- 影响：关键的应用效率机制问题被误记为无答案。
- 修复：补充“应用层发布、配置变更、时间重合、每请求/单位请求资源、资源消耗”等释义。
- 防复发：新增该问法的回归测试，必须命中缓存命中率事实 `f2`。

## 2026-08-19：Benchmark v0.2 / project-03 / 条件 C（第三次）

- 状态：`CAL2-010` 在首问后人工中断，未保存、需再次重试。
- 发现：模型询问新增云成本中哪个资源类别贡献的绝对增量最大；成本分解事实 `f1` 可以直接回答，但旧触发词使用“资源类型/费用构成”，没有覆盖该自然问法。
- 影响：首个诊断性分解问题被误记为无答案。
- 修复：补充“新增云成本、资源类别、贡献最大、绝对增量”等表达并加入回归测试。
- 结构性结论：连续校准已证明关键词 Oracle 需要大量逐句维护。它可用于最小原型，但在正式效果实验前必须增加独立语义 Oracle 或逐题人工复核，且继续报告机器匹配与人工结论的差异。

## 2026-08-19：Benchmark v0.2 / project-03 / 条件 C（第四次）

- 状态：`CAL2-010` 在第 4 问后人工中断，未保存；纯关键词校准路径到此停止。
- 发现：模型询问回滚命名空间迁移或修复缓存后，能否恢复命中率并降低计算成本；回放事实 `f3` 已直接验证这一点，但又因释义不同未命中。
- 结论：这不是值得继续逐条补词的偶发错误，而是关键词匹配不适合开放自然语言提问的重复证据。
- 改造：API 模式默认使用隔离语义 Oracle 选择尚未揭示事实的 `fact_id`，仍返回本地固定事实原文；同时保留关键词结果并统计不一致率。
- 限制：当前未配置独立 Oracle 时会复用受测模型端点，仅用于校准。正式实验必须换成独立 Oracle 模型或逐题人工复核。

## 2026-08-19：Benchmark v0.2 / 12 次均衡校准完成

- 状态：计划的 `CAL2-001` 至 `CAL2-012` 已完成；其中前 9 次使用关键词 Oracle，后 3 次使用隔离语义 Oracle。
- 天花板：12/12 次在提问前已选中最佳行动，未通过正式实验门槛；提问后为 11/12。
- 概率：概率质量改善均值为 `+0.1048`，但主要表示对既有正确选择增加信心，不能证明问题发现能力。
- 反例：`research-01/C` 提问后决策效用下降 7；`project-02/B` 的 5 个细分诊断问题均超出事实表覆盖，不能把无答案率直接当作低质量。
- 决定：停止 v0.2 条件效果比较。下一版采用反事实成对案例，并将问题质量与事实可回答性拆分。
