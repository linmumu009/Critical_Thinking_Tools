# Benchmark v0.3：N/A 三种子确认报告

日期：2026-08-19  
模型：qwen3.8-max  
模型种子：1、2、3  
范围：4 个反事实案例 × N/A × 2 个隐藏分支 × 3 个种子  
有效样本：24 个成对单元、48 个模型会话

## 总体评估：可带限制分享

三种子结果不支持把 A 普通提问设为通用默认干预。跨 12 个“案例 × 种子”配对单元，A 的反事实概率分离增量均值为 `+0.510`，N 原生模型为 `+0.463`，平均差只有 `+0.048`。A 在 9/12 个单元中高于 N，但种子级差值从 `+0.204`、`+0.064` 变为 `-0.125`，且种子 3 中 N 在大多数汇总指标上反超。

更稳定的信号不是“A 普遍有效”，而是强烈的案例依赖：A 在运营和研究案例中 3/3 个种子都优于 N；产品案例基本打平；项目案例中 A 在后两个种子重复陷入无法回答的登录统计，三种子均值明显低于 N。

因此，A 应继续作为所有新工具必须比较的强基线，但不能替代 N，也不应作为当前产品的唯一默认提示。下一版方法应直接优化“选择一个既能区分竞争解释、又能由当前证据回答的问题”，而不是单纯鼓励多提问。

## 对“如何发现好问题”的含义

### 1. 原始问题不是“大模型不会提问”

N 在产品案例中三种子均值 `+0.728`，在种子 3 的项目案例达到 `+0.850`。当竞争机制容易被语言化，或模型第一问就对准关键分叉时，原生能力已经很强，额外提示可能没有收益。

### 2. 普通提问改善的是部分任务的搜索方向

A 在运营和研究案例中连续三个种子胜出。这两例都要求在竞争机制之间主动寻找能改变行动的证据：路由故障对运力不足、测量漏记对样本构成。明确要求通过提问改善决策，可能帮助模型更愿意搜索反证，而不是维持初始选择。

### 3. 普通提问也会放大错误的问题路径

项目案例的 A 在种子 2 和 3 都围绕登录次数、每周活跃率和工单数量反复追问；这些问题看似合理，却不能命中固定事实中的权限覆盖或工作流摩擦。A 没有强制比较竞争解释，也没有要求先判断问题能否由现有证据回答，因此会持续深挖错误口径。

### 4. 下一版应优化“问题选择”，不是“问题数量”

当前证据指向一个更窄、也更可测试的目标：每轮选择一个最可能改变最佳行动、能够区分至少两个竞争解释、并可由当前证据源回答的问题；获得足够证据后立即停止。这个目标比继续串联更多思考工具更贴近已观察到的失败原因。

## 验证报告

### 总体判断：可带限制分享

- 种子 3 的进度账本包含 8 个唯一结果文件和 16 个唯一会话，N/A 各 4 个成对单元，四个案例均完整覆盖。
- 16 个会话均为 Benchmark v0.3、qwen3.8-max、模型种子 3、`semantic_api` Oracle。
- 从原始会话重新计算全部种子 3 成对指标，与保存结果最大差异为 0。
- 种子 3 的协议偏离总数为 0；会话与结果目录中未发现 API Key 或 Bearer 凭证字段。
- 研究 A 第一分支发生一次瞬时读取超时，内置的一次重试成功；没有产生不完整结果或重复成对单元。

### 必须保留的限制

1. 只有 4 个合成案例，每类任务仅 1 个案例；案例异质性不能外推为领域规律。
2. 三个种子共享同一案例，不是 12 个独立案例；不提供把重复种子当独立样本的显著性检验。
3. 服务端即使接收 seed，也不保证完全确定；这里测到的是提示条件与运行波动的组合。
4. Oracle 复用受测模型，可能偏好相似措辞；正式研究仍需独立 Oracle 或条件盲人工复核。
5. 无答案率同时受问题质量和固定事实覆盖影响，但 A 在项目案例的重复失败已足以作为提示设计诊断信号。
6. 当前只完成 N/A 多种子确认；B 的案例异质性和重设计后的 C/D 尚未测试。

## 决策与下一步

1. N 与 A 都保留为后续实验基线；不再把 A 称为通用默认方法。
2. 新增 D“最小判别问题”条件：每轮只问一个同时满足行动敏感、竞争解释区分和证据可答的问题，足够即停。
3. 在运行 D 前冻结提示、停止规则和主指标；先用当前 4 例做开发校准，正式比较必须加入未参与提示设计的新案例。
4. 扩充每类至少多个案例，并以案例为聚类单位报告不确定性；不要用更多种子代替更多案例。
5. 导出 N/A/D 的条件盲问题包，人工评价决策相关性、分叉辨别力、具体性和数据缺口价值。
6. 正式研究使用独立 Oracle，并抽样人工审计 `NONE` 与事实命中的边界。

当前结论应表述为：**普通提问在部分案例中稳定改善问题发现，但总体增益很小、成本更高，并在项目案例中重复失败；真正需要优化的是判别性且可回答的问题选择，而不是统一增加提问步骤。**
