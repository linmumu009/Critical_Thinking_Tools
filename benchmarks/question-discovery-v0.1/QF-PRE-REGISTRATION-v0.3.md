# 条件 Q/F“证据菜单与证据契约”开发预注册

日期：2026-08-20

基准：Question Discovery Benchmark v0.3

冻结条件：Q 与 F，提示词见 [evidence-menu.md](prompts/evidence-menu.md) 和 [evidence-contract.md](prompts/evidence-contract.md)

## 研究问题

E“显式解释状态机”成功禁止目标复用，却在 63 个问题中得到 55 次无事实回答，主指标只有 `+0.196`。路径审计显示，模型经常把一个合理机制扩写成包含多个指标、分组和反事实重算的复合数据请求，无法适配有限事实表。

本轮把“生成问题”和“选择问题”拆开：

- Q 检验模型只获得一组已知可回答的原子证据问题时，能否按决策价值选择正确问题。
- F 在相同证据菜单上增加竞争解释、行动映射和不可复用状态，检验显式状态是否比单纯菜单选择带来额外收益。

这对应两个不同假设：`Q − N` 主要反映可用证据边界和问题候选的价值；`F − Q` 才反映竞争解释状态的增量。原生模型 N 继续计入比较，不能只比较两个新条件。

## 固定证据接口

每个公开案例增加 4 项 `evidence_catalog`：

1. 每项只有中性 `E1`～`E4` 和一个预先写好的有限问题，不包含答案值。
2. 两个隐藏分支看到逐字相同的目录。
3. 每个目录项在每个隐藏分支中恰好映射一条固定事实，因此合法选择不会返回 `NONE`。
4. 目录同时覆盖两个主要竞争机制、干预可行性或支持证据，以及至少一个干扰项。
5. 控制器按 `evidence_id` 确定性返回本地事实，不调用语义 Oracle，也不允许模型自由改写目录问题。
6. N/A/D/E 的公开载荷和 Oracle 行为保持不变；证据目录只对 Q/F 可见。

“原子”在本轮指一个目录项对应一个固定证据单元，不要求事实只能包含一个数字。目录是在查看当前案例事实后构造的，所以只能用于开发测试，不能当作独立确认材料。

## 条件 Q：原生证据菜单

Q 不使用竞争解释或其他思考工具。每轮模型只能输出一个尚未尝试的 `EVIDENCE_ID`，控制器执行对应问题并返回事实；证据足够时输出 `DECIDE`。4 个目录项最多各选一次，因此最多获得 4 条事实。

Q 用于回答：如果问题已经被整理为可回答候选，原生模型是否善于选择最能改变行动的一项？

## 条件 F：竞争解释证据契约

F 先登记 H1/H2/H3 三个解释。每项包含具体机制、一个目录 `evidence_id` 和对应行动；三个证据与三个行动均必须不同。每轮模型只选择一个尚未尝试的 TARGET，控制器执行该解释绑定的目录问题。三个目标最多各一次，因此最多获得 3 条事实。

F 用于回答：在证据可答性已由接口保证后，显式竞争解释状态是否能改善问题排序与停止决策？

## 证据地位与固定比较

- 开发运行：4 个反事实案例 × Q/F × 3 个模型种子 × 2 个隐藏分支。
- 总量：24 个成对单元、48 个模型会话。
- 模型种子：1、2、3。
- 随机化种子：20260828、20260829、20260830。
- 每个模型种子使用独立、可恢复的进度文件。
- 历史参照：相同案例与模型种子下冻结的 N、A、D、E 结果。
- N 是无思考工具、无证据菜单的总体系统参照；Q 是隔离 F 状态增量的直接参照。

历史条件与 Q/F 不是同期运行；差值只用于开发推进。正式确认必须使用未参与目录设计的新案例，并同期随机运行 N、A、Q、F。

## 指标

### 主指标

`counterfactual_separation_gain`：提问后相对提问前，对正确隐藏分支行动的概率分离增量。

### 次要指标

- `post_choice_accuracy`
- `both_post_decisions_correct`
- `correct_option_probability_gain`
- `mean_probability_quality_improvement`

### 选择质量、成本与协议护栏

- 平均证据选择数，即 `mean_questions_used`
- 首次选择命中 critical 事实的会话比例
- supporting 与 distractor 事实的选择率
- 获得足够证据后是否停止
- `model_call_count`：只计受测模型；F 的解释计划与任何格式修复均计入
- Q 的 EVIDENCE_ID 唯一率与保存状态一致性
- F 的解释计划完整率、行动与 evidence_id 唯一率、TARGET 唯一率和保存状态一致性
- `protocol_deviation_count`

Q/F 的无事实率按设计应为 0，因此不再作为效果门槛；任何合法目录选择返回 `NONE` 都是实现或案例映射失败，需要修复后完整重跑受影响单元。

## 条件 Q 的开发推进门槛

Q 只有同时满足以下条件，才以“证据菜单基线”进入未见案例：

1. 三种子主指标均值不低于 `+0.560`。
2. 四个案例中，不得有任何案例的三种子 Q − N 均值低于 `-0.100`。
3. 平均证据选择数不高于 N 的历史均值 `2.71`。
4. 首次选择命中 critical 事实的会话不少于 18/24。
5. 协议偏离总数为 0，EVIDENCE_ID 不复用，保存状态完整一致。

## 条件 F 的开发推进门槛

F 只有同时满足以下条件，才以“竞争解释证据契约”进入未见案例：

1. 三种子主指标均值不低于 `+0.560`。
2. 四个案例中，不得有任何案例的三种子 F − N 均值低于 `-0.100`。
3. 三种子 F − Q 主指标均值不低于 `+0.050`；否则不认为状态机证明了超出菜单本身的价值。
4. 平均证据选择数不高于 N 的历史均值 `2.71`。
5. 首次选择命中 critical 事实的会话不少于 18/24。
6. 协议偏离总数为 0，解释行动、evidence_id、TARGET 均唯一，保存状态完整一致。

Q 与 F 分开判定：Q 通过而 F 失败时，只推进更简单的 Q；F 通过但 Q 不通过时仍需检查是否由少数案例拉高，不能跳过 F − Q 门槛。门槛是开发推进标准，不是显著性检验。

## 排除与停止规则

- 只有未完成两个隐藏分支的基础设施失败单元可以废弃并完整重跑。
- 已完成的错误选择、低分、选择干扰项或过早停止不得排除。
- 初始概率、解释计划、TARGET 或 EVIDENCE_ID 各只允许既有的一次纯格式修复，并计入协议偏离。
- 证据目录缺项、重复映射、分支不对称或合法选择无法返回事实属于基准实现错误；在运行前由验证器阻止。
- 进度文件只把完整成对单元计为完成；孤立会话不进入汇总。
- 在 24 个 Q/F 成对单元完成前，不修改目录、提示、控制器或推进门槛。

## 结论边界与后续确认

Q/F 不直接测试模型能否从开放世界生成新问题，而是测试模型能否从明确的可回答问题集合中选择高价值问题。即使成功，也只能支持“提供证据边界或候选问题能改善决策”，不能声称模型已经学会开放式问题发现。

正式确认需要新增未参与目录设计的案例，由与答案构造分离的人员先定义证据目录，并同期随机运行 N、A、Q、F。报告必须分别呈现整体系统效果 `Q/F − N` 和状态增量 `F − Q`，不能用前者替代后者。
