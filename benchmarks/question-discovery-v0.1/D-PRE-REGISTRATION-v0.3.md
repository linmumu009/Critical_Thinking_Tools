# 条件 D“最小判别问题”开发预注册

日期：2026-08-19  
基准：Question Discovery Benchmark v0.3  
冻结条件：D，提示词见 [minimal-discriminative.md](prompts/minimal-discriminative.md)

## 研究问题

通用的“通过提问改善决策”指令 A 在三个种子中只比 N 原生模型获得 `+0.048` 的平均反事实概率分离增益，多问 `0.67` 个问题，无答案率高 `0.124`，并在项目案例中重复沿错误统计口径追问。

D 测试一个更窄的假设：强制每轮只选择同时满足“行动敏感、解释判别、证据可答”的问题，并在证据足够时停止，能否比单纯鼓励提问更稳定地发现改变行动的证据。

## 证据地位

D 是在查看当前 4 个案例的 N/A 三种子结果后设计的。因此，这 4 个案例是开发集，D 在其上的任何结果都只能用于调试和决定是否进入新案例，不能称为独立确认或正式效果证明。

提示词以项目 v0.15.0 提交中的文本为冻结版本。运行开始后若修改任何实质规则，必须使用新的条件名或版本，并把修改前后的结果分开报告。

## 固定比较

- 开发运行：4 个反事实案例 × D × 3 个模型种子 × 2 个隐藏分支。
- 总量：12 个成对单元、24 个模型会话。
- 模型种子：1、2、3；每个种子使用独立、可恢复的进度文件。
- 历史参照：同一案例和模型种子下已经冻结的 N/A 结果。
- 运行顺序：每个种子内部随机化四个案例的顺序。
- 问题预算：最多 5 个；不得给 D 额外事实或额外轮次。

历史参照只能回答“D 是否值得进入新案例”。由于运行时间不同且 D 已受开发集结果启发，不把历史 N/A 与 D 的差异解释为无偏因果估计。

## 指标

### 主指标

`counterfactual_separation_gain`：提问后相对提问前，对正确隐藏分支行动的概率分离增量。

### 次要指标

- `post_choice_accuracy`
- `both_post_decisions_correct`
- `correct_option_probability_gain`
- `mean_probability_quality_improvement`

### 护栏

- `mean_questions_used`
- `mean_no_fact_answer_rate`
- `protocol_deviation_count`
- 案例级 D − N 与 D − A 差值

## 进入新案例的开发门槛

D 只有同时满足以下条件，才原样进入未参与提示设计的新案例：

1. 三种子主指标均值至少比历史 N 与 A 中的较高者 `+0.050`；当前目标为不低于 `+0.560`。
2. 四个案例中，不得有任何案例的三种子 D − N 均值低于 `-0.100`。
3. 平均问题数不得高于历史 A 的 `3.38`。
4. 平均无答案率不得高于历史 A 的 `0.585`。
5. 协议偏离总数必须为 0；基础设施失败或格式修复必须单独记录。

`+0.050` 是开发推进所需的最小实践差异，不是统计显著性阈值。若 D 未通过，不通过增加种子掩盖失败；先分析问题路径并创建新版本。

## 排除与停止规则

- 只有未完成两个隐藏分支的基础设施失败单元可以废弃并完整重跑。
- 已完成的低分、无事实回答或错误决策不得排除。
- API 的瞬时超时、429 或 5xx 仍只允许现有的一次自动重试。
- 进度文件只把完整成对单元计为完成；孤立会话不进入汇总。
- 在 12 个 D 成对单元完成前，不根据中途结果改提示或开发门槛。

## 后续确认设计

通过开发门槛后，正式比较必须：

1. 使用未参与 D 设计的新反事实案例，并且每类包含多个案例；
2. 同期随机运行 N/A/D，避免历史批次差异；
3. 以案例为聚类单位估计不确定性，不把重复种子当独立案例；
4. 使用独立 Oracle 或条件盲人工复核；
5. 对问题做条件盲评分，至少覆盖行动相关性、分叉辨别力、具体性和数据缺口价值。
