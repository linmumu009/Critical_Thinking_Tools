# Benchmark v0.3 四条件成对校准报告

日期：2026-08-19  
模型：qwen3.8-max  
模型种子：1  
范围：4 个反事实案例 × N/A/B/C × 2 个隐藏分支  
有效样本：16 个成对单元、32 个模型会话

## 总体评估：可带限制分享

本轮结果足以验证反事实成对基准和四条件比较是否有用，也足以决定下一轮校准重点；但只有 4 个案例、1 个种子，Oracle 仍复用受测模型，不能据此宣称某种思考工具具有普遍效果。

最稳定的当前信号来自 A 普通提问基线，而不是更复杂的工具。A 在 4/4 个案例上都比 N 原生模型获得更高的反事实概率分离增量，并在 4/4 个案例中最终同时选对两个隐藏世界。B 在产品案例上达到全轮最高分，但跨案例波动很大；C 平均没有超过原生模型，且问题最多、无答案率最高。

## 主要发现

### 1. 原生模型已经具备一定问题发现能力

N 在产品和研究案例中能根据问题回答同时区分两个隐藏世界；主指标平均为 +0.331。它不是“不会提问”的空白对照。它的主要失败发生在需要推翻强先验的运力与工作流分支：模型反复询问细分计数，却没有直接比较竞争机制。

### 2. 简单提问指令比复杂工具更稳定

A 没有指定 QFT、STORM 或钢人步骤，只明确要求逐个提问改善决策。它是唯一在 4 个案例中全部实现双分支正确的条件，并且每个案例的主指标都高于 N。

当前最合理的解释不是“A 已被证明最好”，而是复杂框架可能增加了搜索负担；一个清晰的任务目标和有限问题预算可能已经足以触发模型的原生诊断能力。

### 3. B 有最高峰值，但强烈依赖案例

B 在产品案例中每个隐藏世界只问 1 个问题，两个正确行动最终概率均为 0.90，主指标 +0.890。但在运营和研究案例中低于 N，并经常在获得一条关键事实后继续追问更细数据。

这表明工具串联可能在竞争解释清晰、关键分叉容易语言化时有效，但在开放诊断任务中也可能造成步骤过多或过度搜索。

### 4. C 暂未显示增益

C 的平均主指标比 N 低 0.031，平均使用 3.88 个问题，无答案率 0.769，均为四条件最差。它在研究案例中经常询问更精细的样本量、置信区间和日志计数，但未优先选择事实表中可以改变行动的最小证据。

在扩大样本前，应先简化 C 的流程，突出“当前哪个单一答案最可能让最佳行动发生变化”，并加入获得足够证据后提前停止的规则。

## Oracle 审计

重点复核了两个疑似漏配：

1. 运营 B 询问“可承接订单量较昨日下降多少”，固定事实给出“区域车辆减少 38%”。由于问题与事实单位不同，`NONE` 属于严格但可辩护的拒答。
2. 研究 C 询问“能否在本周五前用服务器日志重建事件”，固定事实证明已经能用服务器日志补回事件，但没有回答完成时限。`NONE` 同样可辩护。

本轮没有确认需要事后改分的 Oracle 错误。关键词与语义 Oracle 的高不一致主要来自关键词匹配过宽，不能反向证明语义 Oracle 错误。

## 验证报告

### 方法与数据完整性

- 16 个结果文件对应 16 个唯一成对单元，无重复或缺失。
- N/A/B/C 各 4 个单元，每个案例包含全部 4 个条件。
- 32 个会话均为 Benchmark v0.3、qwen3.8-max、模型种子 1、`semantic_api` Oracle。
- 从原始会话重新计算全部成对指标，与保存结果最大差异为 0。
- API Key 未写入任何会话；协议偏离总数为 0。

### 仍然存在的高影响限制

1. 每个条件只有 4 个案例，均值容易被单个案例影响。
2. 只有一个声明种子，且服务端重跑并非完全确定。
3. 产品案例四条件早于其余案例运行，时间与运行顺序没有完全平衡。
4. Oracle 复用同一模型，可能偏好相似措辞；正式实验需要独立 Oracle 或人工复核。
5. 当前问题审计不是条件盲评，不能作为正式人工质量分。
6. 案例来自人工构造，尚未验证对真实用户问题的外部效度。

## 决策与下一步

1. 将 A 与 N 进入多种子确认阶段，作为主要比较。
2. 保留 B 为探索条件，但先不要因产品案例高分宣布胜出；需要验证其案例异质性。
3. 暂停扩展当前 C，先缩短提示并增加“最小判别问题、足够即停”规则。
4. 导出隐藏条件标签的逐题盲评包，评价决策相关性、分叉辨别力、具体性和数据缺口价值。
5. 下一轮至少增加两个种子，并保持案例内 N/A/B/C 配对；在看到跨种子方差后再确定正式样本量。

当前结论应表述为：**在这 4 个反事实案例、1 个种子的开发校准中，普通提问基线最稳定；复杂思考工具没有表现出一致增益。**
