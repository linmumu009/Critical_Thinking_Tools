# Benchmark v0.4：候选问题生成器正式运行报告

报告日期：2026-08-20

运行日期：2026-08-20

模型：qwen3.8-max

模型种子：1、2、3

范围：4 个全新反事实案例 × 6 个条件 × 2 个隐藏分支 × 3 个种子

有效样本：72 个成对单元、144 个模型会话、48 份候选问题工件

## 结论：两阶段方向有信号，但原生生成器和三种思考工具都未通过预注册门槛

把“生成候选问题”和“从可回答菜单中选择证据”拆开后，原生生成器 G0 的反事实概率分离增量为 `+0.712`，高于同期原生端到端 N 的 `+0.621`，差值为 `+0.091`；G0 还把平均无事实回答率从 N 的 `0.285` 降为 0，并在 12/12 个成对单元中让两个隐藏分支都选择正确行动。这支持两阶段架构的基本方向。

但 G0 没有达到冻结的候选质量门槛：12 份候选集中只有 6 份同时覆盖两个隐藏分支的全部 critical 证据，低于要求的 8 份；平均目录匹配率为 `0.521`，低于 `0.600`。因此不能按预注册把当前 G0 原样推进到扩展案例。

QFT 风格 GQ 和 STORM 风格 GS 都改善了候选质量：两者各有 7/12 份候选集实现两分支 critical 全覆盖，平均最低分支覆盖从 G0 的 `0.750` 提高到 `0.792`；目录匹配率分别为 `0.708` 和 `0.656`。然而，它们只比 G0 多 1 份全覆盖候选集，未达到“至少多 2 份”；下游主指标相对 G0 也只有 `+0.027` 和 `+0.011`，未达到 `+0.050`。两者均不通过工具增量门槛。

双向钢人 GB 的下游主指标为 `+0.724`，但候选生成最弱：只有 2/12 份候选集实现两分支全覆盖，平均最低分支覆盖 `0.542`，平均唯一证据数 `3.33`。这说明钢人论证可以组织支持/反对理由，却不自动等于能生成覆盖充分、与现有数据接口精确对齐的原子问题。

因此，本轮最稳妥的判断是：**大模型在已有、可回答的问题菜单上仍然很强；把候选生成独立出来是正确的工程分解，但当前原生、QFT、STORM 风格和双向钢人生成器都没有稳定解决“提出好问题”。GQ 是候选生成层最有希望的版本，尚不足以声称有效。**

## 运行前修订与数据地位

冻结设计见 [CANDIDATE-GENERATION-PRE-REGISTRATION-v0.4.md](CANDIDATE-GENERATION-PRE-REGISTRATION-v0.4.md)。首次连通时，当前 qwen3.8-max 的仅思考模式使生成器/匹配器超过两次 120 秒读取窗口；同时，规范化菜单不含 critical 事实时触发通用计分器除零。此时三个进度账本的 `completed` 均为空。

在首个完整成对单元前做了有记录的运行参数修订：空 critical 集合的命中率定义为 0；所有受测调用、生成器、匹配器和语义 Oracle 统一使用 `max_tokens=1536`、`thinking_budget=512`。案例、提示、随机顺序、问题预算、指标和推进门槛均未改变。限长前的 3 次未完成失败保留在进度账本中，相关成对单元从生成开始完整重跑。

修订后连续完成 72/72 个注册单元，没有新的 API、空响应、写盘或状态失败。

## 对“怎样发现好问题”的含义

1. **已知问题的验证与选择不是主要瓶颈。** 四个生成系统只要菜单中包含一条合适事实，选择器通常能在 1～2 次选择内做出正确决策。
2. **“可答性”与“判别性”必须分开测。** GQ 的目录匹配率最高，但仍只有 7/12 份候选集同时覆盖两个相反机制；生成很多能回答的问题，不等于覆盖了能改变结论的问题。
3. **多视角有帮助，但会重复。** GQ/GS 提高覆盖和唯一证据数，也带来约 1.2～1.3 个重复映射。下一版应显式要求“每题检验不同机制”，并在生成阶段做答案盲去重。
4. **双向钢人更适合重构论证，不适合作为默认问题生成器。** 它围绕现有立场构造强支持/反对论证，却容易漏掉数据接口中真正可区分原因的观测。
5. **不能用 100% 最终准确率宣布问题发现已解决。** 合成案例、有限菜单和强选择器让下游选择接近天花板；候选全覆盖仍只有 2～7/12，说明开放问题发现能力远未通过。

## 下一步

> 路线更新（2026-08-20）：原定人工盲审已由[全自动条件盲审计](AUTOMATED-MAPPING-AUDIT-PROTOCOL-v0.4.md)替代。审计[已完成](automated-review-v0.4/AUTOMATED-SENSITIVITY-REPORT.md)：双评审映射一致率 `0.901`、kappa `0.868`，但仲裁共识与原匹配有 `17.45%` 不一致。下列第 1 项不再要求人工参与；当前应先修匹配接口，再开发 GQ2。

优先级不是继续堆叠思考工具，而是修复候选生成与证据接口之间的两处断点：

1. 根据已完成的全自动盲审，先修候选—目录匹配接口；原匹配与仲裁共识的 `17.45%` 差异已超过预设修复门槛。
2. 匹配接口稳定后，以 GQ 为起点设计 GQ2：先生成互斥机制，再为每个机制生成一个“当前数据能完整回答”的原子问题，并在不知道答案的情况下去重。
3. 为下一批案例提高难度：增加语义相近但行动价值不同的证据、弱干扰项和目录缺口，降低选择器天花板。
4. 保留 N 和 A；下一轮同时报告生成质量、原匹配/自动仲裁共识差异、选择器下游增量和完整 API 成本。

- 没有发现 API Key 或 Bearer 凭证字段，没有结果/会话重复引用，没有分支或条件标签错配。
- 3 条限长前失败记录保留；72 个完成单元均来自完整重跑，修订后没有新增基础设施失败。

### 必须保留的限制

1. 每类只有一个合成案例；三个种子共享案例，不能当作 12 个独立现实案例或显著性证据。
2. GQ/GS/GB 是本仓库的简化适配器；GS 没有外部检索、专家对话和追问，不是完整 STORM/Co-STORM；结果不能外推为原方法的直接验证。
3. 匹配器与受测模型来自同一模型配置，可能共享语义偏差；后续全自动盲审的三个角色也复用同一模型，所以它能检查提示稳定性，但不能消除同模型相关偏差。
4. 模型只能访问预写的六项证据能力，仍不是无限开放世界的“未知的未知”。
5. 选择器在所有生成条件上达到 100% 最终准确率，存在下游天花板；候选覆盖和概率分离比准确率更有诊断价值。
6. 服务端接受 seed 不代表逐 token 确定；报告描述的是当前模型、提示、运行参数和服务状态的组合。

当前结论应表述为：**候选生成—盲匹配—统一选择的两阶段系统在同期实验中优于原生自由提问，但原生生成器没有达到候选覆盖门槛；QFT 和 STORM 风格提高候选覆盖，却没有形成预注册要求的下游增量；双向钢人不适合作为默认候选问题生成器。全自动盲审又发现 `17.45%` 的映射差异，所以下一步应先修匹配接口，再开发强调互斥机制、数据可答性和答案盲去重的 GQ2。**
