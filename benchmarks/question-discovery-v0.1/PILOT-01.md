# API 小批次试点 01

## 结论先行

API 调用、逐轮协议、隐藏事实 Oracle、自动计分、失败中断和断点续跑链路已经可用，但当前案例不适合直接扩展到剩余 99 次。9 次正式运行中有 8 次在提问前已经选择最高效用选项，主指标“决策改善”出现严重天花板效应。

本试点不能用于判断 A、B、C 哪种方法更好。它的作用是校准实验设施并发现设计缺陷。

## 设置

- 日期：2026-08-19
- 模型：`qwen3.8-max`
- 正式运行：随机计划中的 `QD-001` 至 `QD-009`
- 条件分布：A 1 次、B 5 次、C 3 次；该前缀本身不平衡
- 每次问题预算：最多 5 问
- 排除：所有标记为校准、协议失败或人工中断且未保存的尝试

## 校准发现

试点期间发现并修复了三类问题，详见 [CALIBRATION.md](CALIBRATION.md)：

1. 合理的短期结局问题因自然语言表达不同而未命中已有事实。
2. 模型用 `DECISION` 提前结束时，控制器把可恢复输出误判成致命错误。
3. 单独实体词“东区”导致替代运力问题错配到地区分布事实。

所有修复均增加了真实问题文本回归测试；当前测试总数为 15。

## 为什么暂不运行剩余 99 次

当前公开行动选项及其内部 `option_id` 对真实机制提示过强，例如名称直接包含“修复配额提示”“回退身份核验”等信息。模型即使不提问，也经常能从选项措辞猜中预设最佳行动。这样测到的主要是选项识别能力，而不是发现好问题的能力。

此外，关键词 Oracle 对自然语言变化仍较脆弱。虽然本次逐项校准修复了已观察问题，但不能假设剩余案例不会出现新错配。

## 下一步

在继续正式实验前应完成第二版基准：

1. 将公开 `option_id` 改为中性的 `option_a`、`option_b` 等，避免英文标识泄漏机制。
2. 重写过度提示答案的选项标签，使各选项在初始简报下都合理。
3. 增加提问前后的置信度或概率分配；即使最终选项不变，也能测量证据带来的校准改善。
4. 为每例加入自然语言释义回归集，并在正式运行前由未参与案例编写的人做 Oracle 盲测。
5. 用新版案例重新进行均衡小试点，通过后再运行完整矩阵。
