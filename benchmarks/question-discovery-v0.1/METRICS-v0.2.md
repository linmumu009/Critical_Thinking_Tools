# v0.2 指标框架

## 要支持的决定

判断问题发现漏斗（C）是否值得替代直接提问（A），以及它相对既有工具串联（B）的增量价值。指标必须区分“本来就猜对”与“通过好问题变得更确定、更正确”。

## 主要指标

### 1. 概率质量改善

模型在提问前后为四个行动选项分配总和为 1 的概率。以预设最佳行动为真实类别，计算归一化多分类 Brier 质量：

```text
probability_quality = 1 - Σ(p_i - y_i)² / 2
probability_quality_improvement = post_quality - pre_quality
```

范围为 0～1，越高越好。即使提问前后的首选行动相同，只要证据使概率更准确，该指标仍能捕捉改善。它是 v0.2 的首要指标。

风险：合成案例假定存在唯一最佳行动，真实决策的效用不确定性没有完全进入评分。

### 2. 决策效用改善

```text
decision_improvement = post_utility - pre_utility
```

保留 v0.1 指标，用于测量提问是否实际改变行动质量。它直接对应项目目标，但在模型提问前已选对时会触顶，因此不能单独使用。

## 驱动指标

- `best_option_probability_change`：最佳行动概率的提问前后变化。
- `key_unknown_recall`：已揭示关键未知权重占比。
- `critical_fact_hit_rate`：已揭示关键事实占比。
- `probability_information_efficiency`：每个问题带来的概率质量改善。

这些指标解释主要结果如何产生，不能取代主要指标。例如命中很多事实但概率质量不改善，不算成功。

## 护栏

- `no_fact_answer_rate`：Oracle 没有可返回新事实的问题比例。
- `oracle_match_disagreement_rate`：隔离语义 Oracle 与关键词原型的事实选择不一致率。
- `protocol_deviation_count`：可恢复的输出协议偏离次数。
- `questions_used`：实际问题数。
- `pre_choice_probability_consistent` / `post_choice_probability_consistent`：选择的行动是否具有最高主观概率。
- 人工盲评：虚构前提、不可回答、虚假平衡、敏感信息风险和用户负担。

## 防泄漏与位置控制

- 受测模型只看到 `option_a`～`option_d`，看不到内部机制型 ID。
- 每个行动使用单独的 `public_label`；验证器检查隐藏泄漏词不会出现在公开简报或标签。
- 最佳选项位置在 12 个案例中均衡为 A/B/C/D 各 3 次。
- 同一案例的 A/B/C 条件保持相同选项顺序，避免条件比较混入顺序差异。

## 进入完整实验的门槛

先运行一个均衡的 12 次校准集，每个领域和条件均有覆盖。只有同时满足以下条件才恢复完整矩阵：

1. 提问前最佳行动概率的中位数低于 0.75，避免概率指标同样触顶。
2. 至少 25% 的运行在提问前未选择最高效用行动，确保决策改善仍有变化空间。
3. Oracle 错配或漏答率低于 5%，且所有确认错误均已加入回归测试。
4. API 致命协议失败率低于 5%；可恢复偏离必须单独报告。
5. A/B/C 各条件至少覆盖 3 个案例，不能用随机计划的不平衡前缀比较效果。

这些是继续投入完整实验的运行门槛，不是宣称方法有效的效果目标。正式效果判断仍需预注册比较规则和更大样本。

关键词 Oracle 只作为原型执行器。完整实验还要求独立语义 Oracle 或逐题人工复核；不能把“未命中触发词”等同于问题不可回答。机器返回与人工复核不一致时，以预先定义的事实表和人工审计为准，并单独报告不一致率。

语义 Oracle 只返回候选 `fact_id`，不能生成答案；系统随后返回固定事实原文。它使用与受测对话隔离的请求。同一模型兼任受测者与 Oracle 只能用于校准，正式比较必须使用独立模型或人工复核，以降低自我措辞偏好。
