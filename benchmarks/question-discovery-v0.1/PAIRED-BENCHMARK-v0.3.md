# Benchmark v0.3：反事实成对案例

## 为什么需要成对案例

v0.2 的 12 次校准中，模型在提问前 12/12 次已经选中最佳行动。即使提问后概率质量提高，也无法区分“发现了关键问题”和“先靠常识猜中，再寻找支持”。

v0.3 的最小预检集包含 4 个公开案例，每个领域一个。每个公开案例有两个隐藏分支：

- 标题、背景、截止时间、选项和问题预算完全相同；
- 隐藏事实不同；
- 两个分支的最佳行动不同；
- 8 个隐藏分支的最佳选项位置在 A/B/C/D 间完全均衡。

受测模型只看到公开案例，不知道抽中了哪个隐藏分支。因此，同一份提问前判断最多只能命中一边。成对准确率的结构上限是 50%，消除了 v0.2 的固定答案天花板。

## 四组案例

| 成对案例 | 公开冲突 | 隐藏分支 1 | 隐藏分支 2 |
|---|---|---|---|
| product-pair-01 | 引导流程与资格规则同期改变 | 引导脚本回归 | 资格规则误排除 |
| operations-pair-01 | 路由策略与承运运力同期改变 | 路由错误 | 运力短缺 |
| research-pair-01 | 测量迁移与样本构成同时可疑 | 暴露测量丢失 | 预设子群不足 |
| project-pair-01 | 单点登录与审批工作流同时上线 | 权限接入失败 | 工作流增加阻力 |

## 使用方式

先检查结构：

```powershell
python paired_benchmark.py validate
```

运行提问前天花板预检：

```powershell
python paired_benchmark.py preflight
```

如果不传 `--mode`，每次启动都会先让你选择：

1. API 自动运行；
2. 当前 Codex 对话直接处理并人工回填。

也可以明确指定：

```powershell
python paired_benchmark.py preflight --mode api --model-seed 11
python paired_benchmark.py preflight --mode direct
```

API 预检对每个“公开案例 × 条件”只调用一次，共 12 次；不会把两个隐藏分支发送给受测模型。结果保存在被 Git 忽略的 `results/paired-preflight-v0.3.json`。

## 预检指标

- `pre_choice_accuracy`：同一公开回答分别按两个隐藏分支计分，理论上限为 0.5。
- `branch_probability_mass`：分配给两个可能最佳行动的总概率。低值表示模型把概率浪费在两个分支都不优的行动上。
- `branch_probability_gap`：两个可能最佳行动之间的概率差。高值表示模型在没有区分证据时过度押注某一分支。

预检通过不代表思考工具有效。它只证明案例不会让模型在提问前同时猜对两个世界。正式效果指标还必须比较：提问后能否根据被抽中的隐藏事实，把概率从错误分支移动到正确分支。

首次 API 预检已经通过，完整结果见 [PREFLIGHT-REPORT-v0.3.md](PREFLIGHT-REPORT-v0.3.md)。

## 下一阶段门槛

1. 4 对案例的公开载荷逐字相同，最佳行动相反，且无隐藏词泄漏。
2. 提问前成对准确率不得超过 0.5。
3. 受测模型不能看到另一个分支或完整事实表。
4. 完整运行前增加盲评问题质量：决策相关性、分叉辨别力、具体性、数据缺口价值。
5. 正式实验使用独立 Oracle 或逐题人工复核。
