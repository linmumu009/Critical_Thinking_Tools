# Benchmark v0.2 校准报告

日期：2026-08-19  
样本：12 次均衡校准运行，每个案例一次；每个条件 4 次  
用途：检验执行链路与测量效度，不作为提示方法效果证据

## 结论先行

v0.2 的 API、逐轮提问、固定事实返回、概率计分和会话保存链路已经可用，但基准仍未达到正式条件比较的门槛。

最主要的问题是选择天花板：12/12 次运行在提问前已经选中事后定义的最佳行动。提问后只有 11/12 保持最佳，其中一次反而转向较差行动。因此，平均概率质量改善主要表示模型对原先已猜中的行动变得更自信，不能证明它发现了更好的问题，也不能用于判断 A/B/C 哪个提示更有效。

第二个问题是事实覆盖：有些没有固定答案的问题仍然高度具体、与决策相关，并能暴露下一步应采集的数据。`no_fact_answer_rate` 只能作为事实覆盖和交互负担指标，不能单独解释为问题质量差。

第三个问题是执行器在校准中途由关键词 Oracle 切换到隔离语义 Oracle。前 9 次与后 3 次不是完全相同的测量流程，条件均值仅用于发现异常，不得排名。

## 两个关键负例

### research-01 / 条件 C

模型提问后从最佳行动转向较差行动，决策效用变化为 -7，概率质量变化为 -0.1975。该案例证明“提出更多问题”并不保证更好决策，评分必须同时保留决策结果和概率校准，不能只奖励问题数量或事实命中。

### project-02 / 条件 B

模型连续询问未达标员工中的接入障碍、成功登录、技术工单、按部门逐周采用率和登录成功率。事实表没有这些特定分母与时间切片，因此 5 个问题均返回无答案，概率质量变化为 -0.0425。

这些问题并非显然低质；它们暴露了能够区分“工具无价值”和“接入失败”的数据缺口。该运行说明固定事实命中率测量的是基准覆盖与问题的交集，而不是问题质量本身。

## v0.3 的设计决定

1. 使用反事实成对案例：公开描述、选项和先验完全相同，只改变隐藏事实与最佳行动。
2. 成对案例必须让不同隐藏分支对应不同最佳行动；不能从选项措辞或常识先验猜中固定答案。
3. 主要效果指标改为“获得隐藏事实后，相对提问前的成对分支区分能力”，概率质量仍保留。
4. 将问题质量和事实可回答性拆开。人工盲评至少标注决策相关性、分叉辨别力、具体性，以及无答案问题是否揭示有价值的数据缺口。
5. 正式比较使用独立 Oracle 模型或逐题人工复核；同模型语义 Oracle 只用于开发校准。
6. 在新案例通过天花板预检前，不启动 108 次完整矩阵，也不对 A/B/C 排名。

## 审计边界

- 前 9 次使用关键词 Oracle，后 3 次使用隔离语义 Oracle。
- 语义 Oracle 只返回固定 `fact_id`，不会生成答案；但当前复用受测模型，仍可能有同模型措辞偏好。
- 本报告使用自动会话指标和逐题事实表核对，没有完成独立双盲人工评分。
- 所有会话文件保存在本地忽略目录，不含 API Key，也未作为正式结果提交。
