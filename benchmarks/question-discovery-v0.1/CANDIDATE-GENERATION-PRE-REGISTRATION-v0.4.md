# Benchmark v0.4：候选问题生成器确认预注册

日期：2026-08-20

状态：正式运行中；首个完整成对单元前做过一次有记录的运行参数修订

## 运行参数修订（2026-08-20，首个完整成对单元前）

初次连通尝试发现当前 `qwen3.8-max` 为仅思考模型：生成器或盲匹配器会在默认最大思考长度下超过两次 120 秒读取窗口。三个进度文件当时的 `completed` 均为空；另发现规范化菜单不含 critical 事实时，通用计分器会除零。按既定失败规则，这些未完成成对单元废弃并完整重跑，失败记录继续保留。

- 修复空 critical 集合的计分：`critical_fact_hit_rate = 0.0`，不改变候选、事实或推进门槛；
- 对所有受测模型调用、生成器、盲匹配器及语义 Oracle 统一设置 `max_tokens=1536`、`thinking_budget=512`；
- 不关闭模型思考，不修改温度、案例、提示、随机顺序、问题预算、指标或推进门槛；
- 运行命令显式记录这两个参数，确保恢复运行与审计可复现。

## 研究问题

Q/F 开发结果表明：给出已知可回答的原子问题菜单后，Q 的反事实概率分离增量达到 `+0.760`，但这不等于模型已经会从开放问题中发现好问题。下一步把系统拆成三个角色：

1. 生成器只看公开案例和可用数据源/字段，生成候选问题；
2. 盲匹配器只看候选问题和可回答问题目录，不看答案、criticality 或最佳行动，移除无法完整回答及证据重复项；
3. 所有生成条件使用同一个 Q 式菜单选择器获取事实并作决策。

本轮回答两个问题：不同生成工具能否比原生生成器产生覆盖更好的可执行问题集合；这些集合经过相同选择器后，能否超过同期运行的 N 原生模型和 A 普通提问。

## 全新确认案例

使用 `cases-v0.4/` 中 4 组新反事实案例，共 8 个隐藏分支：

- 产品：排序模型与商品分类规则；
- 运营：跨仓路由与保温材料；
- 研究：问卷翻译与样本平台；
- 项目：审批矩阵与 OCR 服务。

每组的两个分支具有逐字相同的公开案例、行动选项、`evidence_capabilities` 和六项盲匹配目录，但隐藏事实与最佳行动相反。8 个最佳行动位置在 `option_a`～`option_d` 各出现两次。案例未参与 Q/F 提示和门槛设计，因此相对旧四例是新的确认材料；它们仍由项目维护者构造，不是领域专家金标准。

## 固定条件

| 条件 | 系统 |
|---|---|
| N | 原生模型自由提问，不加思考工具 |
| A | 明确要求通过提问改善决策，不提供具体工具 |
| G0 | 原生候选生成器 → 盲匹配/去重 → 统一选择器 |
| GQ | QFT 风格生成器 → 盲匹配/去重 → 统一选择器 |
| GS | STORM 风格多视角生成器 → 盲匹配/去重 → 统一选择器 |
| GB | 双向钢人生成器 → 盲匹配/去重 → 统一选择器 |

GQ 只改编 QFT 的“生成与评价分离、问题类型扩展”；GS 没有外部检索、专家对话或追问，不是完整 STORM/Co-STORM；GB 是仓库中的组合提示，并无独立实证验证。报告不得把适配器成绩写成原方法的直接验证。

## 生成与匹配协议

### 候选生成

- 每个“案例 × 生成条件 × 模型种子”只生成一次恰好 8 个候选问题。
- 生成器看不到预写的 `evidence_catalog`、隐藏答案、criticality、分支标签或最佳行动。
- 候选集在两个隐藏分支间原样复用，不能分别生成。
- 每题要求为一个原子观察、比较或反事实检验；格式只允许一次不提供新信息的修复。

### 盲匹配与规范化

- 匹配器一次性把 C1-C8 各映射到 E1-E6 或 `NONE`。
- 匹配器只看到六个目录问题的文字，看不到事实值、分支、criticality 或效用。
- `NONE` 候选被移除；多个候选映射同一证据时，只保留原顺序中的第一项。
- 规范化菜单可以少于 4 项，也可以为空；选择预算为 `min(4, 菜单项数)`。
- 菜单为空时，统一选择器不获得证据，直接完成前后判断；不得把低覆盖生成结果作为基础设施失败排除。

当前自动匹配器默认复用配置中的 Oracle 模型；这是可答性接口，不是事实回答器。正式报告必须导出候选—目录映射供条件盲人工复核，并分别报告自动值与人工修正敏感性。

### 统一选择器

- G0/GQ/GS/GB 使用相同的 Q“原子证据菜单”提示和最多 4 项选择预算。
- 选择器只看到规范化后的候选问题，不知道生成条件、原始匹配结果或被移除的问题。
- 控制器按候选绑定的目录项确定性返回本地事实，不再调用语义 Oracle。
- 六个条件都看到相同的公开 `evidence_capabilities`，但只有盲匹配器看到预写问题目录。N/A 保持自由问题，和生成系统同为最多 4 问预算，使用冻结的隔离语义 Oracle；因此 N/A 与生成系统仍是总体系统比较，不是单一提示差值。

## 固定运行量与随机化

- 模型种子：1、2、3。
- 随机化种子：20260901、20260902、20260903。
- 每个种子：4 案例 × 6 条件 = 24 个成对单元、48 个模型会话。
- 三种子合计：72 个成对单元、144 个模型会话。
- 生成器工件：4 案例 × 4 生成条件 × 3 种子 = 48 份。
- 每个种子使用独立、可恢复进度文件；随机顺序同时包含 N/A 和四个生成系统。

## 指标

### 生成器主指标

1. `minimum_branch_critical_coverage`：同一候选集在两个隐藏分支中的较低 critical 证据覆盖率。
2. `both_branches_full_critical_coverage`：两个分支是否都覆盖全部 critical 证据。

### 生成器次要指标

- `catalog_match_rate`：8 个原始候选中被匹配到目录的比例；
- `unique_evidence_count` 与六项目录覆盖率；
- `duplicate_match_count`；
- 规范化菜单项数；
- 格式修复次数；
- 条件盲人工评分：原子性、可执行性、问题间语义重复、行动判别力和目录匹配正确性。

### 下游决策主指标

`counterfactual_separation_gain`：证据交互后相对交互前，对正确隐藏分支行动的概率分离增量。

### 下游次要指标与成本

- `post_choice_accuracy`、`both_post_decisions_correct`；
- `correct_option_probability_gain`；
- `mean_probability_quality_improvement`；
- 平均问题/证据选择数与无事实率；
- 生成器、匹配器、受测选择器和语义 Oracle 调用量分开报告；
- 协议偏离和保存状态完整性。

## 固定比较与推进规则

### 原生生成器 G0

G0 是“候选生成 + 统一选择”的直接系统基线。只有同时满足以下条件，才认为两阶段架构值得进入扩展案例：

1. 12 份候选集中至少 8 份达到两个分支 critical 全覆盖；
2. 平均目录匹配率不低于 0.60；
3. 平均唯一证据数不低于 3.5；
4. 下游主指标不低于同期 N，且四个案例中没有一个三种子 G0 − N 均值低于 `-0.100`；
5. 最终选择准确率不低于 N；
6. 没有保存状态或分支复用错误。格式修复保留计数，但不单独否决内容表现。

### 工具生成器 GQ/GS/GB

每个工具相对 G0 单独判定。只有同时满足以下条件，才声称该工具对候选生成有增量：

1. 两分支 critical 全覆盖的候选集数量至少比 G0 多 2/12，或在 G0 已达 10/12 以上时不低于 G0；
2. 平均 `minimum_branch_critical_coverage` 不低于 G0；
3. 下游主指标 `工具 − G0 ≥ +0.050`；
4. 四个案例中没有一个三种子 `工具 − G0 < -0.100`；
5. 下游最终准确率不低于 G0；
6. 总受测模型调用量不高于 G0 的 1.50 倍；
7. 没有保存状态或分支复用错误。

若多个工具通过，先选下游主指标最高者；差值小于 0.020 时，依次以更高的最小 critical 覆盖、更低调用量和更简单的协议决胜。门槛是开发/确认推进规则，不是显著性检验。

### N 与 A 的地位

N 必须始终报告，是不加思考工具的原生端到端参照；A 是已知强但不稳定的自由提问基线。不能只比较四个生成器，也不能用工具相对 N 的总体优势替代工具相对 G0 的生成增量。

## 排除、失败与停止规则

- 已完成的低覆盖、重复候选、`NONE`、低分、错误选择或协议偏离不得排除。
- 只有未完成两个隐藏分支的网络、API 空响应、进程中断或写盘失败可以废弃，并从生成开始完整重跑该成对单元。
- 格式错误只允许一次纯格式修复，不提供案例新信息；第二次失败使单元停止并记录，不能手工改写模型内容。
- 盲匹配结果在两个分支运行前冻结；不得查看某分支答案后修改映射。
- 72 个成对单元完成前，不修改案例、提示、匹配规则、预算、指标或推进门槛。

## 结论边界

即使某生成器通过，也只能支持：在公开数据能力已知、候选经过盲匹配和去重的有限环境中，该生成协议产生了更有用的问题集合。它不能证明模型解决了无限开放世界的“未知的未知”，也不能把 GS 的结果外推为完整 STORM 的效果。

最关键的成功信号不是问题数量，而是：同一个不看隐藏分支的候选集同时覆盖两种相反机制，并在统一选择器中超过原生生成器和同期端到端基线。
