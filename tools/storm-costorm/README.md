# STORM / Co-STORM：多视角提问与知识策展

- **阶段**：探索主题、发现未知的未知、研究前写作
- **证据状态**：NAACL 2024 与 EMNLP 2024 同行评审系统评估
- **适合**：主题宽、用户不知道该问什么、需要检索与形成研究大纲

## 一句话原理

不要让模型凭空“列十个问题”，而是先发现相关主题中的不同视角，再让不同视角的提问者与有来源的专家进行多轮对话，以追问逐步扩展问题空间。

STORM 是 **Synthesis of Topic Outlines through Retrieval and Multi-perspective Question Asking**。Co-STORM 在此基础上加入多代理讨论、主持人、用户介入和动态思维导图，重点解决用户难以主动发现“未知的未知”。

## 原始流程

### STORM

1. 查找相近主题的高质量资料，从中提取不同写作/研究视角。
2. 每个视角分别与“有检索来源的专家”模拟对话。
3. 根据回答继续追问，而不是预先一次性列完问题。
4. 汇总问题、答案和来源，形成层级大纲。
5. 基于大纲和来源生成长文，并做润色。

### Co-STORM

1. 多个专家代理轮流提出有来源的内容或后续问题。
2. 主持人寻找尚未被讨论的信息，并提出能打开新方向的问题。
3. 用户可观察或介入，改变讨论焦点。
4. 系统持续更新思维导图，降低长对话的认知负担。

## 轻量提示词实现

这不是 STORM 代码的复刻，而是保留其“视角驱动 → 检索 → 追问 → 大纲”机制的手工版。

```text
请用 STORM 风格帮助我探索主题，而不是立即写结论。

目标：[我为什么研究这个主题]
主题：[主题]

按顺序执行：
1. 先检索相近主题的可靠资料，基于资料识别 5-7 个真正不同的研究视角；解释每个视角为什么可能发现其他视角看不到的信息。
2. 对每个视角先提出 2 个高价值问题。问题应指向机制、边界、反例、利益相关者、时间变化或可验证证据，避免只问定义。
3. 用可靠来源回答每个问题，并根据答案再提出 1 个自然的后续问题。区分来源事实、推断与未知。
4. 让“主持人”检查：哪些未知的未知刚刚出现？哪些重要视角仍缺席？补充不超过 3 个问题。
5. 生成一份层级知识地图：已知、争议、未知、最值得继续查证的问题。
6. 暂停并让我选择方向；在我选择前不要生成完整报告。
```

## 质量检查

- 视角是否由相近主题和资料启发，而非职业角色换皮？
- 后续问题是否由前一轮答案自然产生？
- 每条事实是否能追溯到来源？来源是否真的支持该句？
- 是否明确暴露了资料偏差、来源冲突与未覆盖区域？
- 大纲是否反映研究结果，而非沿用模型一开始的预设结构？

## 研究结果与边界

- STORM 论文报告：与大纲驱动的检索增强基线相比，文章被评为“组织良好”的比例绝对提高 25%，覆盖广度绝对提高 10%。这是特定长文任务的比较，不代表所有推理任务都会提高。
- Co-STORM 的用户评估中，70% 的参与者偏好它胜过搜索引擎，78% 偏好它胜过 RAG 聊天机器人。偏好不等同于事实准确率。
- 论文同时指出来源偏差传递、无关事实过度关联等问题。官方项目也明确称生成结果不能直接视为可发表文章。
