# 问题发现漏斗（Question Discovery Funnel）

- **阶段**：从现实信号发现、筛选并验证值得追问的问题
- **证据状态**：基于多项有来源方法的原创组合框架；完整流程尚未独立验证
- **适合**：只有模糊主题、异常或决策困境，尚不确定真正应该问什么

## 要解决的失败模式

现有工具能扩大和检查问题，但仍可能出现：

1. 在用户给出的错误框架内高质量推演。
2. 生成很多措辞不同、认知机制相同的问题。
3. 按“听起来深刻”排序，而不是按回答后的决策价值排序。
4. 由同一个模型扮演多方，产生表面多样、底层相关的错误。
5. 选出的问题没有明确证据路径或可区分的可能答案。
6. 没有用现实反馈淘汰、缩小或重写问题。
7. 把由定义、单调关系或领域共识直接推出的结论包装成研究问题。
8. 没有系统检索先行研究，就把措辞新颖误当成研究空白。

## 核心定义

在这个框架里，一个好问题必须同时满足：

- **真实**：来自可追溯的观察、矛盾、失败、需求或决策，而非模型凭空构造的重要性。
- **有杠杆**：至少两个合理答案会导致不同的判断、优先级或行动。
- **有判别力**：答案能区分竞争解释，而不只是为所有解释再添一个故事。
- **可回答**：能说明需要观察、检索、访谈、测量或实验什么。
- **值得回答**：减少不确定性的预期收益高于时间、金钱、风险和认知成本。

表达清楚只是合格门槛，不是“好问题”的充分条件。

## 八阶段流程

### 0. 写下决策或探索目标

先完成下面一句话：

> 我们需要在 `[时间]` 前决定 `[行动选项]`；现在最可能导致错误决定的不确定性是 `[未知]`。

如果暂时没有具体决策，则写探索目标和停止条件，例如“找到三个有现实证据支持、值得进一步调查的异常机制”。没有决策或停止条件时，后续问题只能标为探索性问题。

### 1. 从现实信号开始，而不是从抽象主题开始

收集最小证据包：

- 观察到什么，预期原本是什么？
- 谁受到影响，谁掌握一手信息？
- 何时、何地出现，在哪些边界内没有出现？
- 有什么原始记录、数据、用户原话或失败案例？
- 哪些是观察，哪些只是解释？

至少包含一个外部于当前大模型的信号。若没有，只能生成“待验证的问题候选”，不得声称发现了真实问题。

### 2. 重构问题：5W1H × 层级移动

使用 Six Honest Serving Men（Who、What、Why、When、Where、How）分别改写问题。每个疑问词至少产生一个与原框架实质不同的表述。

再进行两种层级移动：

- **向上游问 Why**：这个问题服务于什么目标？它可能只是哪个更大问题的症状？
- **向下游问 How**：它通过什么可观察机制发生？怎样知道已经改善？

输出 8–15 个问题表述，标记哪些改变了对象、边界、因果层级、利益相关者或时间尺度。只换措辞的不计入。

### 3. 扩展问题空间

在暂不回答的条件下：

1. 用 QFT 批量产问和转换开放/封闭形式。
2. 用 STORM 式检索寻找不同视角、相邻领域、异常案例和未知的未知。
3. 强制覆盖八种问题家族：描述、测量、因果、机制、边界/反例、比较、干预、价值/利益相关者。
4. 让真实资料、不同人员或独立模型补充；单模型角色扮演不视为独立来源。

### 4. 聚类与去重

按“回答需要依赖的机制或证据”聚类，而不是按文字相似度聚类。每组保留：

- 一个最清晰的问题；
- 一个最反常但合理的问题；
- 一个最容易用现实证据试探的问题。

合并仅改变措辞的问题，保留真正改变因果机制、边界或行动的问题。

### 5. 决策分叉门

每个候选问题必须填写：

| 项目 | 内容 |
| --- | --- |
| 决策 | 回答服务于什么具体决定？ |
| 合理答案 A | 如果是 A，将采取什么行动？ |
| 合理答案 B | 如果是 B，将采取什么不同的行动？ |
| 未知/混合 | 如果证据不确定，将如何处理？ |
| 反转条件 | 什么结果会改变当前首选行动？ |

如果 A、B 最终对应相同行动，则该问题当前决策价值低：删除、降级为背景问题，或重新寻找真正的上游不确定性。

### 6. 信息价值排序

先应用硬门槛，再做相对排序。

**硬门槛**：

- 没有伪造前提或无法核查的“事实”。
- 有至少两个合理答案，且问题没有预设答案。
- 有一条现实可行的证据路径。
- 不违反伦理、安全或隐私约束。

**轻量信息价值判断**：

1. 当前选错行动的可能性有多大？
2. 选错的后果有多大？
3. 这个问题的答案有多大概率改变选择？
4. 可获得的信息能减少多少关键不确定性？
5. 获取答案的全部成本和风险是什么？

使用低/中/高加理由即可。没有决策模型时，不要把主观等级伪装成精确的正式 VOI 数值。

### 7. 廉价现实试探

对排名前三的问题各做一个最小试探：

首先完成两个淘汰门：

1. **常识性/非平凡性审查**：写出最显然的基线答案、仍未解决的不确定性，以及一个可能推翻基线的边界或反例。如果答案仅由定义、单调关系或稳定领域共识直接推出，且没有可检验的边界条件，则淘汰；如果只有特定边界、效应大小、因果机制或反常条件仍未知，则把问题缩小到该非显然增量。
2. **先行研究审查**：分别用问题原句/同义表达、核心机制、相邻领域术语三类检索式查找论文，并沿最近综述和最接近工作的引用链补查。记录最接近工作已经回答了什么、尚未回答什么，以及候选的非冗余增量。未检索时只能标记“未知”，不得声称“尚无人研究”。

然后执行现实试探：

- 查高质量一手资料，确认问题不是已经解决或只剩措辞差异；
- 访谈一位直接受影响者，检查问题是否对应真实经验；
- 查看一小段原始数据或一个反例；
- 写出竞争假设和能排除至少一个假设的观察；
- 检查回答该问题所需的数据是否真的可获得。

试探结果只能有四种处理：**保留、缩小、改写、淘汰**。禁止为了保住最喜欢的问题而把所有结果解释为支持。

### 8. 形成问题契约并循环

最终问题应连同以下内容一起交付：

- 原始现实信号与来源；
- 它服务的决策和使用者；
- 关键概念、边界和时间范围；
- 竞争答案或假设；
- 判别性证据与反转条件；
- 最小下一步、成本和停止条件；
- 当前仍不知道什么。

若最小试探暴露了新对象、新边界或新机制，返回第 1 或第 2 阶段，而不是只润色句子。

## 为什么这样组合

- 问题构造研究显示，主动重构模糊问题与更高质量、更原创的解决方案相关；结构化的 5W1H 提示在实验中提高了问题构造的流畅性、灵活性和原创性。
- Design Council 的 Double Diamond 要求先发现并重新定义问题，再开发和小规模测试方案；它补上了“现实观察”和“迭代”环节。
- QFT 与 STORM 分别补充无评价产问和多视角、有来源的后续追问。
- FINER 提供可行、重要、新颖、合乎伦理和相关等基本筛选维度。
- 信息价值把“有趣”改写为“减少哪个决策不确定性、是否值得付出成本”。
- Strong Inference 要求竞争假设和可排除其中至少一个的关键测试，补上判别性。

这些组件各自的证据不能自动证明此组合流程有效，因此必须配合本文件夹中的实验方案验证。

## 不适用场景

- 已有清晰、标准答案的简单事实查询。
- 必须立即执行、没有探索时间的紧急情况。
- 只需要创意娱乐、无需真实决策价值的自由发散。
- 高风险专业判断中没有合格领域人员和可靠资料参与。
