# 问题发现漏斗实验方案

## 目的

检验问题发现漏斗是否比简单提示和现有工具串联更能产生：

1. 会改变决策的问题；
2. 能命中关键盲点的问题；
3. 用更少提问带来更大决策改善的问题；
4. 同时不过度增加虚构前提、用户负担和成本。

不能只让另一个大模型评价“哪个问题更深刻”。自动问题生成研究指出，常见自动指标与人工判断、可回答性之间可能不一致，评估本身是当前瓶颈。

## 待检验假设

- **H1 决策改善**：使用漏斗后，参与者或代理最终选择的效用/正确率高于基线。
- **H2 关键问题命中**：在固定提问预算内，漏斗更常询问到专家预先标注的关键未知变量。
- **H3 信息效率**：单位问题、时间或 token 带来的决策改善高于基线。
- **H4 安全护栏**：虚构前提率、不可回答问题率和用户负担不显著恶化。

## 对照条件

保持基础模型、可用资料、温度、上下文和最大提问数一致；至少重复多个随机种子。

| 条件 | 方法 |
| --- | --- |
| A：直接基线 | “请提出最多 5 个最重要的问题，然后给建议” |
| B：工具串联 | QFT → STORM 风格扩展 → 双向钢人 → 排序 |
| C：问题发现漏斗 | 现实信号 → 5W1H 重构 → 发散 → 决策分叉 → 信息价值 → 廉价试探 |

## 三类测试任务

### 1. 有隐藏真相的决策案例

构造产品故障、运营异常、研究设计和项目风险案例。每例包含：

- 所有条件都能看到的模糊初始简报；
- 只能由“回答者/oracle”访问的事实表；
- 专家预先定义的关键未知、干扰项、行动选项和效用；
- 已知结果或可判定的最佳行动。

系统逐题提问，oracle 只能按事实表回答。比较提问前后的决策变化。

### 2. 历史回放案例

选取已经完成、根因和结果已知的真实项目，但隐藏结局。让领域人员确认哪些早期信号与问题在当时确实可获得，防止用后见之明设置不公平答案。

### 3. 开放现实案例

由真实使用者带来尚未解决的问题。这里只能依赖盲评、后续采用情况和现实试探结果，不能假装存在唯一标准答案。

## KPI 框架

### 主要结果指标

#### 1. 决策改善（Decision Improvement）

```text
提问后的决策效用或正确率 - 看到问题前的决策效用或正确率
```

这是最重要的结果指标，因为项目目标不是生成漂亮文本，而是减少错误判断。效用函数必须在看输出前由案例设计者预先定义。

#### 2. 决策改变问题率（Decision-Changing Question Rate）

```text
具有至少两个合理答案且预先对应不同动作的问题数 / 全部提出的问题数
```

开放案例由两名领域人员和一名实际使用者盲评；分歧需记录，不能简单让大模型裁决。

### 驱动指标

- **关键盲点 Hit@K**：前 K 个问题命中的预标注关键未知比例。
- **判别性问题率**：答案能排除或显著削弱至少一个竞争假设的问题比例。
- **现实依据率**：能追溯到输入观察、用户陈述或可靠来源的问题比例。
- **非冗余覆盖**：按机制/证据聚类后覆盖的独立问题家族数。
- **试探转化率**：候选问题能形成可执行最小试探的比例。
- **价值校准**：流程事前预测的低/中/高信息价值与实际决策改善是否一致。

### 护栏指标

- **虚构前提率**：问题中包含输入或来源未支持前提的比例。
- **不可回答率**：在给定资源和期限内没有可行证据路径的问题比例。
- **虚假平衡率**：在证据明显不对称时仍制造对称竞争观点的比例。
- **负担**：用户回答轮数、总耗时、token/检索成本和主观认知负担。
- **敏感信息风险**：不必要索取隐私、机密或高风险信息的次数。

## 评审方式

1. 输出随机排序并隐藏条件标签。
2. 至少两名领域评审者独立评分，再由一名目标使用者评价决策价值。
3. 在评分前给出统一量表和正反例。
4. 报告评审一致性和全部分歧；不要只报告平均分。
5. 大模型可协助标注格式、重复和来源，但不得作为唯一质量裁判。
6. 同时报告失败案例，特别是高分问题没有改善决策的案例。

## 最小可行实验

首轮不需要建立大型基准：

1. 准备 12 个案例，覆盖产品、运营、研究和项目决策，每类 3 个。
2. 每个案例运行 A/B/C 三种条件，各运行 3 个随机种子，共 108 次。
3. 每次最多允许提出 5 个问题，oracle 使用固定事实表回答。
4. 由不知道条件的评审者评分，计算主要结果、驱动指标和护栏。
5. 先建立基线分布，再决定正式目标；当前没有数据，不设置武断的提升百分比。

## 通过与否的决策规则

首轮把框架视为“值得继续”需同时满足：

- C 在两个主要指标上均优于 A，并至少一个有明确、稳定的实际差异；
- C 的提升不是仅由更多问题、更多 token 或更多时间解释；
- 虚构前提率和不可回答率没有明显恶化；
- 优势至少出现在两类任务中，而非单一案例类型；
- 人工审查确认结果不是评分规则泄漏或评审偏好造成。

如果只提高问题多样性或专家主观评分，却不提高后续决策，则应判定当前组合没有解决核心问题。
