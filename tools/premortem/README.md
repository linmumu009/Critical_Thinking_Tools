# 事前验尸（Pre-mortem）

- **阶段**：计划审查、风险发现、行动设计
- **证据状态**：广泛采用；完整方法主要是实践协议，核心“前瞻性后见”机制有间接实验支持
- **适合**：团队已有一个准备执行的计划，但担心乐观偏差、沉默或遗漏失败路径

## 一句话原理

不要问“可能出什么问题”，而是假设计划已经惨败，再从未来回看“它为什么失败”，从而让反对意见更具体、更容易说出口。

## 操作流程

1. 让所有参与者了解现有计划。
2. 宣布情景：“现在是未来的某一天，计划已经彻底失败。”
3. 每个人独立写下导致失败的原因，暂不讨论。
4. 轮流每次贡献一项原因，直到收集完；避免领导者先定调。
5. 按可控性、影响、概率、出现时间和可探测性整理。
6. 为高优先风险指定预防动作、早期信号、触发阈值和负责人。
7. 把剩余风险明确写入决策记录，而不是用“已讨论”代替处理。

## 可直接复制的提示词

```text
请主持一次事前验尸。不要评价计划好坏，先假设它已经失败。

计划：[计划]
目标与期限：[目标/期限]
已知约束：[约束]

情景：现在已经到了期限，计划以一种明确、严重且可观察的方式失败了。

请按顺序执行：
1. 先定义“失败”具体长什么样，避免含糊。
2. 从人员、激励、流程、技术、资源、依赖、外部环境、时间和错误假设等角度，独立生成互不重复的失败原因。
3. 将原因按“影响 × 发生可能性 × 难以及时发现”排序，并标注哪些只是推测。
4. 对前 5 项分别给出：最早可观察信号、触发阈值、低成本预防动作、应急动作和负责人角色。
5. 指出一个最可能被团队压低声音、但值得立即讨论的风险。
6. 最后输出一张风险登记表；不要用乐观总结冲淡剩余风险。
```

## 质量检查

- “失败”是否具体到能判断发生与否？
- 原因是否包含计划内部机制，而不只是外部灾难？
- 风险是否被转成可监测的早期信号和触发动作？
- 是否保留少数意见与不确定性？

## 局限

- 它提高风险发现的机会，但不证明发现的风险概率估计准确。
- 生动、容易想象的灾难可能被高估；需要基准率和数据校准。
- 同一模型生成全部观点时错误高度相关，重要项目应让团队成员先独立作答。
- 不能替代正式的安全、财务、法律或工程风险分析。
