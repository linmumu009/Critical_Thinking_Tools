# Critical Thinking Tools

一个用于收集、验证和迭代批判性思维工具的项目，重点研究如何帮助人和大模型提出更好的问题，而不只是生成更长的答案。

## 项目假设

大模型通常擅长围绕一个明确问题检索、归纳、比较和验证，却容易在问题尚未成形时过早作答、顺着用户的初始框架推演，或生成大量看似不同但本质重复的问题。

本项目尝试把成熟的提问、反证和决策方法改写成可复用协议：

1. 先扩大问题空间，发现遗漏视角和“未知的未知”。
2. 再收敛到最有信息价值、最可能改变行动的问题。
3. 最后用竞争假设、反方证据、估计或测试进行验证。

这仍是一个需要验证的项目假设。仓库会明确区分“原方法有证据”“只在特定任务有效”和“提示词改编本身尚未测试”。

## 每张工具卡包含什么

- 方法的核心原理与适用阶段。
- 可重复执行的操作流程。
- 可直接复制的大模型提示词。
- 输出质量检查清单。
- 证据状态、适用边界和失败风险。
- 可追溯的论文或机构来源。

工具的“知名”不等于“有效”。例如 ACH 虽被情报分析领域广泛采用，后续实证研究却给出混合甚至偏负面的结果；本项目仍会收录这类工具，但不会隐藏反证。

## 基准与实验

- [Question Discovery Benchmark v0.4](benchmarks/question-discovery-v0.1/)：以公开描述相同、隐藏事实与最佳行动相反的成对案例，分开测量候选问题生成、证据匹配和下游决策，覆盖产品、运营、研究和项目四类任务。
- 比较 N 原生模型、A 普通提问、B/C/D/E/Q/F 历史协议，以及 G0 原生、GQ QFT 风格、GS STORM 风格、GB 双向钢人四种候选生成系统；以提问前后反事实分支概率分离增量为下游主指标，以双分支关键证据覆盖为候选主指标。
- 提供 API 自动运行与 Codex 直接处理两种入口，以及隔离语义 Oracle、可恢复随机运行计划、自动决策指标和条件盲自动审计。
- [首轮四条件校准](benchmarks/question-discovery-v0.1/CALIBRATION-REPORT-v0.3-seed1.md)：在 4 个案例、1 个种子中，A 普通提问最稳定，复杂工具没有表现出一致增益。
- [N/A 三种子确认](benchmarks/question-discovery-v0.1/CONFIRMATION-REPORT-v0.3-seeds1-3.md)：A 的总体主指标只比 N 高 `+0.048`，且种子 3 被 N 反超；效果呈明显案例依赖，普通提问不能作为通用默认干预。
- [D 开发预注册](benchmarks/question-discovery-v0.1/D-PRE-REGISTRATION-v0.3.md)：冻结“行动敏感、解释判别、证据可答、足够即停”的最小判别问题提示，以及进入未见案例前的效果与成本门槛。
- [D 三种子开发报告](benchmarks/question-discovery-v0.1/D-DEVELOPMENT-REPORT-v0.3.md)：D 主指标为 `+0.488`，介于 N 与 A 之间，只通过 5 项推进门槛中的 3 项；失败集中在无事实反馈后不能可靠切换竞争解释。
- [E（D2）开发预注册](benchmarks/question-discovery-v0.1/E-PRE-REGISTRATION-v0.3.md)：将三个竞争解释、证据目标和已尝试状态变成可检查协议，冻结效果、成本、加权无事实率和状态完整性门槛。
- [E 三种子开发报告](benchmarks/question-discovery-v0.1/E-DEVELOPMENT-REPORT-v0.3.md)：E 主指标只有 `+0.196`，低于 N、A、D；状态机阻止了目标复用并减少问题数，却因复合数据请求与固定证据粒度错配而产生 `0.873` 的问题加权无事实率。
- [Q/F 开发预注册](benchmarks/question-discovery-v0.1/QF-PRE-REGISTRATION-v0.3.md)：用分支对称且不含答案的原子证据菜单拆分“生成问题”和“选择问题”；Q 测菜单价值，F 测竞争解释状态相对 Q 的额外价值，N 继续作为原生系统参照。
- [Q/F 三种子开发报告](benchmarks/question-discovery-v0.1/QF-DEVELOPMENT-REPORT-v0.3.md)：Q 与 F 主指标分别为 `+0.760` 和 `+0.693`，均高于历史 N；简单菜单 Q 反而比竞争解释契约 F 高 `0.067`，说明当前突破来自可回答候选问题，而不是额外状态机。
- [候选问题生成器 v0.4 预注册](benchmarks/question-discovery-v0.1/CANDIDATE-GENERATION-PRE-REGISTRATION-v0.4.md)：用 4 组全新反事实案例比较原生、QFT 风格、STORM 风格和双向钢人生成器；候选问题经不看答案的匹配/去重后交给同一选择器，并与同期 N/A 自由提问比较。
- [候选问题生成器 v0.4 正式运行报告](benchmarks/question-discovery-v0.1/CANDIDATE-GENERATION-REPORT-v0.4.md)：72 个同期成对单元显示两阶段 G0 主指标比原生 N 高 `+0.091`，但候选覆盖和匹配率未过门槛；GQ/GS 改善候选覆盖却未达到相对 G0 的下游增量，GB 候选覆盖最弱。
- [API 模式 1](benchmarks/question-discovery-v0.1/API-MODE-1-FROZEN-v0.4.md)：固定现有双条件盲自动评审加分歧仲裁流程，不因模式 2 改写提示、种子、配置槽位或正式结果；[人工盲审包](benchmarks/question-discovery-v0.1/BLIND-MAPPING-REVIEW-PROTOCOL-v0.4.md)仅作为可选材料。
- [API 模式 2](benchmarks/question-discovery-v0.1/API-MODE-2-PROTOCOL-v0.4.md)：独立执行“问题契约提取→单项证据覆盖证明→反例验证”，使用专用 API 配置、进度和结果目录；只有两种模式都锁定后，才允许只读比较。
- [候选映射全自动盲审结果](benchmarks/question-discovery-v0.1/automated-review-v0.4/AUTOMATED-SENSITIVITY-REPORT.md)：双评审映射一致率 `0.901`、kappa `0.868`，但仲裁共识与原自动匹配有 `67/384`（`17.45%`）不一致；所有原推进门槛仍失败，下一步先修匹配接口，再开发 GQ2。

## 版本约定

项目采用语义化版本号 `MAJOR.MINOR.PATCH`：

- `MAJOR`：包含不兼容的重大调整。
- `MINOR`：新增向后兼容的功能。
- `PATCH`：向后兼容的问题修复或小幅改进。

每次项目更新都应：

1. 更新本 README 中的“版本更新记录”。
2. 提交本次全部相关变更，提交信息应简洁说明更新内容。
3. 将提交推送至 GitHub 远程仓库。
